# Six-Step UI Flow Implementation Plan (Plan E)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Wire the verified engine into a 6-step wizard that a non-expert can complete: import a Flex Query, review (with quarantine + substantial-holder toggle), add prior-year losses and surtax income, see an explained summary (or a clear fix-it block), and export.

**Architecture:** `WizardShell` owns state and orchestrates `parseFlexXml → fetchRatesMap → calculateTax`. Every engine `Explanation { code, params }` is rendered by a single `<Explain>` component via next-intl. The UI never computes tax; it renders `EngineOutput`.

**Tech Stack:** Next.js 16 (App Router), React, next-intl 4 (en + he/RTL), Tailwind 4, Vitest + @testing-library/react.

## Global Constraints
- Bilingual (en + he RTL): every new string in **both** `messages/en.json` and `messages/he.json`, including one message per `Explanation.code`.
- Blocking vs quarantine (ADR-0008): a blocked result shows **fix-it guidance** and no numbers; quarantine shows numbers plus a "not included" list.
- Explanations rendered from domain codes (ADR-0005) — the UI supplies no tax prose of its own beyond labels.
- Statelessness: prior-year loss, other income, and the token live in React state only; never persisted (ADR-0004/0006).
- 6 steps: Tax Year → Import → Review → Additional details → Summary → Export.

## File Structure
- `components/wizard/WizardShell.tsx` (modify) — 6-step state + orchestration + `EngineOutput`.
- `components/common/Explain.tsx` (create) — renders `Explanation`.
- `components/wizard/Step2Import.tsx` + `components/import/*` (modify) — Flex guide, file routing, Activity Statement rejection.
